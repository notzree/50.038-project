MVP limitations (current)

1) Small audio subset
- Current runs use a small subset of locally downloaded songs (around a few hundred), which limits generalization.

2) Label imbalance
- The target appears_in_region is highly imbalanced (roughly ~2.5% positives in current runs).
- This makes high accuracy easy to achieve while still missing many true positives.

3) Limited feature scope
- Model currently uses basic audio descriptors and region only.
- It does not yet use artist, release timing, social trend, or marketing context.

4) Coarse label definition
- The MVP target is binary "appears at least once in region top200".
- It does not model timing (7/30 day horizon), peak rank, or chart longevity yet.

5) Evaluation simplification
- Current threshold tuning uses test predictions for quick MVP diagnostics.
- Future versions should tune on a validation split and keep test fully held out.


Roadmap after MVP

Phase 1: Data scale-up
- Download/extract features for many more songs.
- Add stronger QC and duplicate handling.

Phase 2: Better labels
- Add time-window targets (e.g., appears in 7/30 days), and later longevity targets.
- Handle right-censoring for songs near dataset end.

Phase 3: Better features
- Add richer audio embeddings.
- Add context features (artist prior performance, release period, trend signals).

Phase 4: Modeling improvements
- Compare additional models and calibrate probabilities.
- Tune decision thresholds per region if needed.

Phase 5: Product/UI
- Build region map + timeframe slider.
- Show per-region probability and confidence bands over time windows.
